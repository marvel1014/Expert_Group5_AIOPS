# Spec Delta

## Purpose

为值班人员提供告警、故障事件、拓扑与诊断报告的统一下钻视图，使"发现告警—查看事件—触发诊断—阅读报告"形成一条不依赖命令行的可演示闭环。

## ADDED Requirements

### Requirement: 告警与事件列表

系统 SHALL 在单页看板中提供告警列表与故障事件列表，支持按主机、服务、严重级别、状态与时间范围筛选、分页与排序；列表 MUST 显示严重级别、状态、首末出现时间与是否已完成诊断。

#### Scenario: 按条件筛选告警

- **WHEN** 用户选择主机与严重级别筛选条件
- **THEN** 列表只显示满足全部条件的告警，并保留分页信息

#### Scenario: 空结果展示空状态

- **WHEN** 筛选条件没有匹配结果
- **THEN** 看板显示空状态提示而不是报错或空白页面

### Requirement: 故障事件详情

系统 SHALL 提供故障事件详情页，展示聚合后的成员告警、涉及节点与拓扑关系、根因候选、诊断状态与结论，以及该事件关联的报告入口。

#### Scenario: 查看事件聚合详情

- **WHEN** 用户从事件列表进入某故障事件详情
- **THEN** 页面展示成员告警数量、涉及节点、根因候选排序、诊断结论与报告链接

### Requirement: 看板概览指标

系统 SHALL 在看板首页展示指定时间范围内的告警总数、聚合后事件数、压缩比、严重级别分布与诊断准确率，指标 MUST 与后端统计接口一致。

#### Scenario: 概览指标可见

- **WHEN** 用户打开看板首页
- **THEN** 页面展示告警总数、事件数、压缩比、严重级别分布与最近一次评估的诊断准确率

### Requirement: 实时刷新

系统 SHALL 在新告警或新故障事件产生后 5 秒内更新看板列表与概览指标，刷新机制 MUST 在后端不可用时进入可恢复的重试状态且不导致页面崩溃。

#### Scenario: 新告警自动出现

- **WHEN** 通过 Webhook 注入一条新告警且看板处于打开状态
- **THEN** 看板在 5 秒内显示该告警或对应事件，无需手动刷新页面

#### Scenario: 刷新失败可恢复

- **WHEN** 后端在轮询或推送过程中暂时不可用
- **THEN** 看板显示连接异常提示，后端恢复后自动继续刷新

### Requirement: 诊断与报告交互

系统 SHALL 允许用户从事件详情触发诊断、查看诊断进度状态、在失败时重试，并在诊断完成后进入报告页查看或导出报告。

#### Scenario: 触发诊断并查看状态

- **WHEN** 用户在事件详情点击"开始诊断"
- **THEN** 页面展示排队或执行中状态，并在完成后自动展示根因结论与报告入口

#### Scenario: 诊断失败可重试

- **WHEN** 诊断因后端错误进入失败状态
- **THEN** 页面展示失败原因与重试按钮，重试成功后展示诊断结果

### Requirement: 页面可用性与错误状态

系统 SHALL 以静态资源方式提供可访问的单页应用，页面切换 MUST 不产生整页刷新；加载中、接口错误与数据为空时 MUST 分别显示明确的加载、错误与空状态。

#### Scenario: 接口错误显示提示

- **WHEN** 看板请求列表接口失败
- **THEN** 页面显示错误提示与重试入口，已加载的其他区域保持可用
