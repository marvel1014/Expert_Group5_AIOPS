# Spec Delta

## Purpose

把根因诊断结论转化为值班人员可直接执行的分步排查与修复报告，明确每一步的预期结果、风险等级与回滚方式，降低从"知道原因"到"完成修复"之间的操作门槛。

## ADDED Requirements

### Requirement: 报告自动生成

系统 SHALL 基于故障事件与指定版本的诊断结果自动生成报告，报告 MUST 包含故障摘要、影响范围、根因结论、证据引用、分步排查、修复建议、验证方式、回滚方案与风险提示；大模型不可用时 MUST 使用模板生成结构完整的报告。

#### Scenario: 基于成功诊断生成报告

- **WHEN** 调用方对已有成功诊断的故障事件请求生成报告
- **THEN** 系统返回包含上述全部章节的报告，且根因结论与诊断版本一致

#### Scenario: 降级诊断仍生成报告

- **WHEN** 诊断处于降级状态时请求生成报告
- **THEN** 系统仍生成结构完整的模板化报告，并在报告中标注结论来自降级诊断

### Requirement: 分步排查与修复建议

系统 SHALL 输出按顺序编号的排查步骤与修复建议，每一步 MUST 包含操作动作、预期结果、风险等级与失败时的回退动作；风险等级 MUST 区分低、中、高。

#### Scenario: 高风险步骤显式标注

- **WHEN** 报告中的修复建议涉及重启服务、删除数据或修改配置
- **THEN** 该步骤被标注为高风险，并附带回滚动作与需人工确认的提示

#### Scenario: 步骤顺序可执行

- **WHEN** 调用方阅读报告
- **THEN** 排查与修复步骤按由低风险到高风险、由诊断到验证的顺序编号排列

### Requirement: 报告版本与历史

系统 SHALL 将报告与具体的诊断版本绑定，并为报告维护版本号与生成时间；重新生成报告 MUST 创建新版本且不覆盖历史版本，默认查询 MUST 返回最新版本。

#### Scenario: 重新生成报告

- **WHEN** 调用方对同一诊断再次请求生成报告
- **THEN** 系统创建版本号递增的新报告，旧版本仍可查询，默认查询返回新版本

### Requirement: 报告导出

系统 SHALL 支持把报告导出为 Markdown 与 JSON 两种格式，导出响应 MUST 使用 UTF-8 编码并携带可读文件名；导出内容 MUST 与当前版本报告一致。

#### Scenario: 导出 Markdown 报告

- **WHEN** 调用方请求以 Markdown 格式导出报告
- **THEN** 系统返回 UTF-8 的 Markdown 内容与包含事件标识和版本号的文件名

#### Scenario: 导出不存在的报告返回错误

- **WHEN** 调用方导出一个不存在的报告标识
- **THEN** 系统返回未找到错误，而不是空文件

### Requirement: 人工复核标记传递

系统 SHALL 在诊断被标记为需要人工复核时，在报告顶部显示复核提示与缺失证据；报告 MUST NOT 把低置信度结论表述为确定事实。

#### Scenario: 低置信度报告显示复核提示

- **WHEN** 为低置信度且需人工复核的诊断生成报告
- **THEN** 报告顶部包含人工复核提示，且根因表述使用"可能""待确认"等非确定性措辞
