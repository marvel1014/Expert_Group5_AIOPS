# Spec Delta

## Purpose

提供统一、可校验、幂等的告警与日志入口，把来自模拟源与外部系统的异构遥测数据规范化，为后续降噪、关联与根因分析提供可信的原始证据。

## ADDED Requirements

### Requirement: Webhook 告警接收

系统 SHALL 提供 HTTP Webhook 接口接收单条或批量告警，对必填字段做校验，并返回受理结果与告警标识；字段缺失或类型非法时 MUST 返回校验错误而不是静默丢弃。

#### Scenario: 接收单条合法告警

- **WHEN** 客户端向 Webhook 接口提交包含告警来源、主机、服务、规则、严重级别、消息与发生时间的 JSON
- **THEN** 系统返回成功受理状态、告警 ID 与该告警是否被去重的标记

#### Scenario: 缺少必填字段被拒绝

- **WHEN** 客户端提交的告警缺少主机或规则字段
- **THEN** 系统返回参数校验失败，响应中指出缺失字段，且该请求不产生任何告警记录

#### Scenario: 批量告警部分失败

- **WHEN** 客户端一次提交多条告警且其中部分条目非法
- **THEN** 系统返回每条条目的受理结果，合法条目写入成功、非法条目附带错误原因，整体响应标明成功与失败数量

### Requirement: 告警规范化与幂等去重

系统 SHALL 将告警规范化为统一内部模型（来源、主机、服务、规则、严重级别、标签、时间、指纹、首末出现时间与重复次数），并按指纹在去重窗口内合并重复投递；同一指纹的重复告警 MUST 复用既有告警标识并累加重复次数。

#### Scenario: 重复告警合并

- **WHEN** 同一主机、同一规则、同一来源的相同告警在去重窗口内被再次提交
- **THEN** 系统返回相同告警 ID，重复次数加一，末次出现时间更新，不新增告警记录

#### Scenario: 超出窗口后视为新告警

- **WHEN** 相同指纹的告警在去重窗口之外再次提交
- **THEN** 系统创建新的告警记录并返回新的告警 ID

### Requirement: 关联日志接入与查询

系统 SHALL 接收带错误堆栈的日志记录（时间、主机、服务、级别、消息、堆栈、追踪标识），并支持按主机、服务、时间范围与追踪标识检索日志片段，以便根因分析引用原始证据。

#### Scenario: 按主机与服务检索堆栈日志

- **WHEN** 调用方按主机与时间范围查询日志，且该范围内存在错误堆栈记录
- **THEN** 系统返回匹配的日志条目，包含消息、堆栈文本与追踪标识

#### Scenario: 无匹配日志返回空集

- **WHEN** 调用方查询的时间范围内没有匹配主机或服务的日志
- **THEN** 系统返回空列表与成功状态，而不是报错

### Requirement: 可复现的故障注入

系统 SHALL 提供模拟故障注入能力，能够按场景一次性生成互相带时序关联的多主机、多服务告警，并生成与告警追踪标识关联的错误堆栈日志；注入行为 MUST 可重复执行。

#### Scenario: 注入一次多主机故障

- **WHEN** 运维人员对某故障场景触发注入，指定告警数量与时间压缩倍率
- **THEN** 系统写入带时序关系的多条告警及对应堆栈日志，且这些记录可通过查询接口检索

#### Scenario: 重复注入不报错

- **WHEN** 同一场景被连续注入两次
- **THEN** 两次注入均成功完成，告警按去重规则合并或新增，且每次注入的追踪标识所关联的堆栈日志证据均被保留
