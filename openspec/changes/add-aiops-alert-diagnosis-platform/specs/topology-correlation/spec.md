# Spec Delta

## Purpose

利用机房服务与主机的上下游拓扑识别告警之间的因果关系，把沿调用链扩散的数百条告警压缩为一个故障事件，并给出最可能的根因节点候选，替代人工在告警瀑布中猜测起点。

## ADDED Requirements

### Requirement: 拓扑建模与查询

系统 SHALL 支持以服务、主机为节点，以有向依赖边描述上下游调用关系的拓扑定义，从配置文件加载并对外提供拓扑查询接口；拓扑节点 MUST 包含唯一标识与类型，依赖边 MUST 标明上游与下游。

#### Scenario: 查询拓扑

- **WHEN** 调用方请求拓扑数据
- **THEN** 系统返回节点列表与有向依赖边列表，每条边标明上游节点与下游节点

#### Scenario: 非法拓扑被拒绝

- **WHEN** 加载的拓扑中存在指向不存在节点的依赖边
- **THEN** 系统拒绝该拓扑并报告非法边的位置与原因，保留原有可用拓扑不变

### Requirement: 上下游因果关联

系统 SHALL 在关联时间窗内收到多个拓扑相关节点的告警时，依据有向依赖关系将它们归入同一个故障事件；归入事件的告警 MUST 在拓扑上可达，且事件记录压缩前的告警数量与涉及节点。

#### Scenario: 上游故障导致下游告警

- **WHEN** 数据库服务告警后，其下游订单服务与网关服务在关联时间窗内相继告警
- **THEN** 系统将这些告警归入同一故障事件，事件涉及节点包含数据库、订单服务与网关服务

#### Scenario: 无拓扑路径不合并

- **WHEN** 两个节点之间不存在任何有向路径，且两者告警发生在关联时间窗内
- **THEN** 系统不将两者归入同一故障事件

#### Scenario: 超出关联时间窗不合并

- **WHEN** 拓扑上可达的两个节点告警时间差超过关联时间窗
- **THEN** 系统不基于拓扑关系将两者归入同一故障事件

### Requirement: 根因候选排序

系统 SHALL 为每个故障事件输出根因节点候选列表，候选排序 MUST 综合节点在拓扑中的上游位置、节点首条告警的先后、严重级别与是否命中规则化故障特征，并给出每个候选的排序依据。

#### Scenario: 最上游节点优先

- **WHEN** 同一故障事件中数据库节点（最上游）与两个下游服务节点都产生告警，且数据库告警发生最早
- **THEN** 数据库节点排在根因候选首位，响应中说明其上游位置与最早告警作为排序依据

#### Scenario: 同层节点按严重级别排序

- **WHEN** 多个根因候选在拓扑中处于相同上游层级
- **THEN** 严重级别更高、告警更早出现的候选排在前面

### Requirement: 拓扑缺失时降级

系统 SHALL 在节点缺少拓扑定义或拓扑为空时降级为不使用拓扑的聚类结果，并明确标记该事件为未做拓扑关联；系统 MUST NOT 凭空推断不存在的依赖关系。

#### Scenario: 未知节点降级

- **WHEN** 告警涉及的节点不在拓扑定义中
- **THEN** 系统仍生成事件，但事件标记为拓扑信息缺失，根因候选仅依据告警自身特征排序

### Requirement: 事件压缩统计

系统 SHALL 对外提供事件压缩统计，返回原始告警条数、故障事件数、压缩比与拓扑关联命中率，用于验证"百条告警压缩为一条"的效果。

#### Scenario: 查询压缩统计

- **WHEN** 调用方查询指定时间范围的压缩统计
- **THEN** 系统返回原始告警数、故障事件数、压缩比与事件中完成拓扑关联的比例
